## 新增授权：语音播报真机测试

用户随后明确允许播报测试，仍禁止动作。通过 `scripts/run.py --check-speech` 调用公开 `T1Client.command` 一次，文本为“你好，机器人语音播报测试。”。独立进程配置仅启用 `speak`、`motion.enabled=false`；实际只有五个读取客户端和一个 TTS 客户端，未创建速度发布器。工作台的只读配置未修改。

- PlayTts 返回 `accepted`、`vendor_code=0`、`tts_success=true`，服务调用耗时 40 ms，回传 trace_id 与请求一致。
- 播报前采集 2 秒：峰值 566、RMS 128.30；请求后采集 14 秒：峰值 2,251、RMS 221.89（16 kHz / mono / s16le）。仅保留电平统计，未保存录音。
- 采集结束后正确回收音频进程；音量读回 20%、静音 false，没有调用音量或静音 setter。
- 本次 TTS 请求 1 次，运动请求 0 次，其他设备写请求 0 次，无自动重发。

该结果确认 TTS 服务成功受理且采音链路有电平变化；SDK 不提供播放完成事件，未将电平变化当成具体播报内容或物理播放完成的证明。

## 页面控制与一键启动

用户明确指出“不做动作测试”只限制助手联调，不限制用户在页面操作。因此本机 `config/local.json` 已改为 `read_only: false`；本轮完整 SDK 扩展后示例配置也默认开启控制。上一阶段只读查询显示 31 个具名动作入口、TTS、表情、音量及静音接口可用；当时浏览器检查确认按钮启用，没有点击执行按钮，检查期间未发送设备写请求。服务可用和按钮解锁不等于动作已完成真机验收。

`./start.sh --no-browser` 启动成功，随后重复执行正确复用已有服务。普通 `./start.sh` 在桌面环境会打开浏览器；缺少页面构建时自动构建。修正了重复 SDK 启动时的初始化顺序：先取得命令日志锁，再建立原生连接，防止锁冲突留下未回收的 ROS 实例。
