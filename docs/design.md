# T1 SDK Lab 设计与实施计划

初稿：2026-10-19；完整接口更新：2026-10-20。源项目：`/home/yoga/RoboWeave`；交付目录：`/home/yoga/robot-sdk-debug-lab`。

## 目标与边界

独立的 T1 机器人 SDK 脚手架，提供可复用 Python SDK、HTTP/WebSocket API 和 React + TypeScript 调试页面。不依赖 RoboWeave 主应用，不引入大模型、ASR、聊天、Q1 或模型下载流程。提取已有 T1 适配层，保留厂家 SDK 接口版本校验、真实回执与过期数据标记。

用户明确区分“助手不做机器人测试”与“用户可以在页面操作”。最终交付默认 `read_only=false`，包含完整 SDK 控制入口；启动不会自动执行动作。用户可主动配置只读模式，界面与后端共同遵循该配置。初始阶段完成了读取链路与一次明确授权的 TTS 验证；完整接口扩展阶段按最新要求不做机器人功能测试，仅核对源码并构建。由用户开启的 HAL 流在结束／退出时按厂家规定发送阻尼帧。

## 架构

```text
React 页面 → FastAPI /api + WebSocket
                    ├─ T1Client → 提取的 T1 ROS 适配层 → ROS 2 / 厂家 aimdk_msgs
                    ├─ VideoHub → FFmpeg → 机器人 RTSP
                    └─ 机器人 PulseAudio TCP → PCM → Web Audio 播放
```

- Python 3.10 / ROS 2 Humble；React + TypeScript + Vite。SDK 和 Web 服务共用一个独立 Python 环境。
- `src/t1_lab/sdk/`：公开 SDK、配置、只读策略；`src/t1_lab/_vendor/`：按实际依赖提取的 T1 适配代码；`src/t1_lab/api.py`：页面 API；`web/`：前端；`scripts/`：配置、启动、只读诊断。
- 厂家 SDK 固定 commit `fe2e186c867391ec78b301accdc91f0260ad0ff3`，按固定源码独立编译完整 T1 消息包并校验 55 份接口定义；提供独立准备入口，运行时不依赖原项目 Python 包或服务。厂家二进制、现场地址和媒体不提交。
- 本地配置保存机器人地址、ROS domain、DDS 配置、左右目 RTSP、音源与声道。配置示例使用占位地址。访问凭据留在服务端；默认本机监听。

## 页面设计

深色导航栏搭配浅灰背景、白色卡片和薄荷绿状态色；较大留白、清晰字号、精简边框。主区域以视频为视觉中心，右侧是设备概览和实时音频，下方为 SDK 控制与调用记录。支持桌面与窄屏布局。

1. 实时画面：左右目切换、流状态、截图下载、最近截图；RTSP 与 SDK 单帧分别标记来源，失败不以静态图片冒充直播。
2. 音频监听：点击开启机器人麦克风监听，PCM 流经 WebSocket 输入 Web Audio，展示真实电平、连接与播放状态，可停止；不采集浏览器麦克风。
3. 设备信息：电池、运动模式、控制源、音量/静音、关节与触摸遥测，显示来源、单位、时效及缺失原因；提供原始 JSON。
4. SDK 操作：姿态、预设动作、有界短时移动、停止、TTS、音量/静音、表情；只读模式显示锁定原因，接口仍可查阅。请求记录区显示实际返回结果。
5. 离线与错误：后端/ROS/视频/音频状态分别呈现；没有硬件时页面仍可加载，不伪造设备在线和遥测。

## API 与资源生命周期

- `GET /api/health`、`/api/state`、`/api/capabilities`：连接信息、能力和状态。
- `GET /api/video/stream?camera=left|right`：共享 FFmpeg MJPEG 流；最后一个订阅者退出后回收进程。
- `POST /api/snapshots`：SDK 或视频截图；`GET /api/snapshots` 与图片下载。
- `WS /api/audio`：16 kHz / mono / signed 16-bit PCM，首帧发送格式，断线取消采集；监听租约与超时防止孤儿进程。
- `POST /api/commands`、`/api/motion`、`/api/motion/stop`：只读守卫、参数约束、SDK 执行与真实回执；不自动重试写操作。
- `GET /api/events`：有界调用记录；`/docs`：API 文档。

## 扩展计划：完整厂家接口接入

用户进一步要求补齐舵机、单关节底层控制及遗漏 SDK，并明确本轮不进行机器人测试、页面保持可操作。此前的高级接口范围限制由本扩展计划替代。只做本地源码核对、静态检查和构建，不运行真机验收脚本或发送任何试用请求。

- [x] P8：以固定厂家源码及接口说明为基准，建立全部服务、话题、媒体协议的覆盖清单和可复现参数 schema。
- [x] P9：完整服务调用、原始响应、话题订阅／发布、持久回执；舵机位置速度、14 关节 HAL、6 关节上肢独立接入。关节发布在后端执行有限时长与租约，结束按厂家 HAL 约定发送阻尼帧；不把浏览器帧率当成伺服频率。
- [x] P10：独立舵机与关节页面、完整 SDK 参数调用台、灯光／音频文件／屏幕视频／关机入口；控制只因实际参数、连接或设备条件提示失败，不因未进行真机测试锁定页面。
- [x] P11：补充厂家文档中存在但源码缺失的 AudioCapture / AudioPlayback 消息，记录来源；接入音频 TCP 播放。保留未实测标记及厂家文档不一致项。
- [x] P12：静态核对所有厂家服务与消息、构建 Python / React / 原生消息包，更新一键启动和范围文档；不做设备功能测试。

舵机 SetServo 是 0–90 度的形态舵机；HAL JointCommandArray 和 MC McCustomJointCommand 是不同的关节控制通道。HAL 依赖机器人低层开发模式，MC 上肢依赖 BIPED_CUSTOM_UPPER；这些厂家前置条件在页面说明，不自动改设备开发模式。单关节目标会结合其他关节反馈组成完整帧，避免省略字段被硬件当作零目标。

## 扩展计划：切换网络地址与提交代码

用户需要在机器人热点与局域网之间切换 IP。连接配置采用一个机器人 IPv4 地址，同时作用于 ROS 发现、RTSP、机器人麦克风与 TCP 播放。原有独立媒体服务器地址保留，绑定机器人地址的媒体使用 `{robot_ip}` 模板。每次启动生成实际 DDS 配置，避免遗漏旧 IP。
